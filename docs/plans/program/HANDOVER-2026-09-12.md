## 7. Recurring lessons from this week (read before dispatching agents)

Agents branch from the integration branch and touch overlapping files: merge with both intents kept (a dedicated Opus "merge hand" with the file list works; two such merges took 8 files each). Never `git add -A && git commit` on a conflicted tree: three commits landed with `<<<<<<<` markers this week; always `grep -rl "^<<<<<<<" web/src web/messages docs supabase` first. JSON catalogues merge by union of both sides; `package.json` test lanes by union of file lists; `decisions.md` by keeping both and renumbering. An agent that "waits for lint"/"waits for a monitor" repeatedly is stuck: kill its stray process by PID and take the worktree over. Cloud agents (Cursor) cannot prove anything on the isolated DB: always re-prove (objects, privileges, race scripts) before applying to production; that caught three real bugs (pgcrypto resolution, a two-winner table move, an outbox idempotency race). "Fixture" failures in a case run are often app defects (RLS gaps); read the message, not the label. The owner wants speed and will say "skip the process"; the answer is to put the work first, not to skip the gate.
