## Critical Gaps Found

1. Phase 8.3 webhook trust updates used a request-scoped Supabase client inside service-role webhook helpers. In a Stripe webhook context, that can fail to upsert `client_trust_state`.

2. Phase 8.3 balance top-ups were not idempotent. A Stripe webhook retry could insert duplicate `client_balance_ledger` rows and double-credit `funded_balance_cents`.

3. `client_balance_ledger_staff_read` referenced `agency_memberships.user_id`, but the table has `profile_id`. Staff ledger reads would fail or leak by broken policy shape depending on database behavior.

4. Workspace/talent subscription staff policies used broad agency-staff checks. They needed `is_staff_of_tenant(...)` scoping to preserve tenant isolation.

5. Phase 3.7 trust/contact write policies lacked explicit tenant-scoped `WITH CHECK` protections. Talent self-upserts also needed to be tied to a real roster relationship in that tenant.

6. `inquiries.trust_level_at_submission` existed without a DB constraint or query index.

7. Docs and implementation drifted on naming: older docs mention `client_trust_level_at_send`, while implementation uses `trust_level_at_submission`. The implemented name is now the live contract unless product chooses to add a compatibility alias.

8. Phase 8.4 commission display passed basis points into a function that expected a plan-tier string. Agency/network fee rows could render at the default studio rate.

9. Phase 8.4 migration is still a foundation only. It lacks source-tenant consistency triggers, DB-enforced transaction state transitions, transaction UI actions, and event logging integration.

10. Prototype parity remains an active requirement. The live prototype currently shows the shared Workspace/Talent shell, clients trust-tier nav copy, and the Website page. Local verification must continue against `http://localhost:3000/` before any deploy/promotion.
