## ⚠️ READ FIRST — the structural contradiction this checklist exists to catch

The execution plan (EP §2, §6 Phase 1, §10) says two things that are **in tension in
today's codebase**, and the spec-guardian's single most important job is to make sure
the implementer resolves it rather than silently shipping the cheaper half:

1. EP §2 / Phase 0–1: *"Wrap the existing engine. Reuse `DirectoryDiscoverSection`
   as-is."* That component renders **`DirectoryCardDTO`** (`web/src/lib/directory/types.ts:30`)
   via **`TalentCard`** (`web/src/components/directory/talent-card.tsx`).
2. EP §10 (HARD gate, DS wins): the card must show a **trust badge**, an
   **agency/independent badge**, and a **denormalized availability signal**.

**`DirectoryCardDTO` has none of those fields.** It has `id, profileCode, displayName,
primaryTalentTypeLabel, locationLabel, fitLabels, cardAttributes, isFeatured, …` — no
`trustTier`, no `agencyName`/`isExclusive`, no `nextAvailableDate`. Those fields exist
only on a **different** type, `DiscoverTalentListItem`
(`web/src/app/(workspace)/[tenantSlug]/_data-bridge/discover.ts:23`), served by the
separate `/api/discover/talents` path that EE verified end-to-end.

Therefore "wrap `DirectoryDiscoverSection` unchanged" and "satisfy EP §10" **cannot
both be literally true** for the canonical Portrait card. The implementer must pick one
and the gate must record it:

- **Path A (spec-faithful):** the Atelier/Portrait canonical render sources cards from
  the Discover data path (`DiscoverTalentListItem` / `loadDiscoverTalents`), so trust /
  agency / availability are real. `DirectoryDiscoverSection` reuse is then partial
  (filters/sidebar/infinite-scroll harness reused; card payload swapped).
- **Path B (engine-reuse, spec-deferred):** ship on `DirectoryCardDTO`, and the §10
  trust/agency/availability boxes **FAIL** until the DTO is extended. This is allowed
  only as an explicitly logged, time-boxed amendment (EP §0 "where this plan and the
  Discover spec disagree, the Discover spec wins — file an amendment, do not silently
  diverge").

CDP-0 below makes this an explicit gate item. Items tagged **[Path-A only]** are
N/A under a logged Path B but their FAIL must be written into the Phase 1 sign-off,
not omitted.
